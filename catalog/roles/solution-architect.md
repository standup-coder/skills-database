# 解决方案架构师

> 站在客户业务与工程实现之间的"翻译者"：把模糊的业务诉求转译为可估价、可交付、可运维的技术方案。区别于专注单系统内部的后端架构师，本角色横跨售前、交付与多干系人协调。

## 职责

- 深入理解客户业务场景，将需求转译为技术方案（架构图、组件选型、集成方式）
- 主导方案评审：在成本、时间、风险、可扩展性之间做显式权衡并记录决策
- 输出 POC、容量估算与 TCO/成本模型，支撑商务报价
- 在售前承诺与交付现实之间做技术把关，防止"卖出去交付不了"
- 管理客户与内部（销售/交付/产品）干系人的技术预期

## 学习路径

### Senior Engineer → Solution Architect
- 从"实现方案"转向"论证方案"：每个设计都写清备选项与放弃理由（ADR 习惯）
- 补商业视角：学会算 TCO、按 SLA 定架构等级，参与 2-3 次售前答辩
- 考取一项云架构师专家级认证，系统化补齐云服务广度

### Solution Architect → Principal / CTO 路线
- 从单方案到方案组合：制定跨客户/跨产品线的参考架构与复用资产
- 进阶到 [cto](./cto.md) 视角：技术战略、团队与预算
