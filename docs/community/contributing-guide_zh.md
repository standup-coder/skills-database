## 行为准则

### 我们的承诺

我们承诺让参与我们项目的每个人都不受骚扰，无论年龄、体型、残疾、种族、性别认同、经验水平、国籍、外貌、种族、宗教或性取向如何。

### 我们的标准

**积极行为包括：**
- 使用友好和包容的语言
- 尊重不同的观点
- 优雅地接受建设性批评
- 关注对社区最有利的事情

**不可接受的行为包括：**
- 挑衅、侮辱/贬损性评论
- 公开或私人骚扰
- 发布他人的私人信息
- 其他可能被视为不适当的行為

## 贡献方式

### 1. 报告问题

发现 bug 或有建议？

- 检查问题是否已存在
- 使用问题模板
- 提供详细信息：
  - 您期望的 vs 实际发生的
  - 复现步骤
  - 您的环境（操作系统、浏览器）

### 2. 建议新技能

技术快速演进！帮助我们保持最新。

**技能建议格式：**
```markdown
**技能名称**: [名称]
**类别**: [Dev/Arch/Testing/Ops]
**级别**: [初级/中级/高级/专家]
**描述**: [简要描述]
**纳入理由**: [理由]
**资源**: [学习材料链接]
```

### 3. 改进文档

- 修正拼写和语法错误
- 澄清令人困惑的部分
- 添加示例和插图
- 翻译成其他语言

### 4. 添加技能生态内容

帮助扩展我们的 AI 技能生态覆盖：

- 研究新的 AI 工具和平台
- 编写整合指南
- 创建对比矩阵
- 记录最佳实践

### 5. 开发工具

技术贡献者可以帮助：

- 网站开发（VitePress）
- CLI 工具
- 技能验证脚本
- CI/CD 改进

## 开始之前

### Fork 和 Clone

```bash
# 在 GitHub 上 Fork 仓库，然后：
git clone https://github.com/YOUR_USERNAME/skills4coder.git
cd skills4coder
```

### 创建分支

```bash
git checkout -b feature/your-feature-name
# 或
git checkout -b fix/issue-description
```

### 进行修改

- 使用您喜欢的编辑器编辑文件
- 遵循我们的格式规范
- 在本地测试您的更改

### 提交

```bash
git add .
git commit -m "类型: 描述

详细解释做了什么以及为什么"
```

**提交类型：**
- `feat`: 新功能或技能
- `fix`: Bug 修复
- `docs`: 文档更改
- `style`: 格式化，无代码更改
- `refactor`: 代码重构
- `test`: 添加测试
- `chore`: 维护任务

### 推送并创建 PR

```bash
git push origin feature/your-feature-name
```

然后在 GitHub 上创建 Pull Request。

## 贡献规范

### 技能列表格式

添加或修改技能时，遵循以下格式：

```markdown
- [ ] **技能名称** - 技能的简要描述
  - 子技能或细节
  - 另一个细节
- [ ] **另一技能** - 描述
```

### 文档标准

**结构：**
- 使用清晰、简洁的语言
- 包含实用示例
- 添加学习资源
- 保持双语支持（中/英）

**格式：**
- 正确使用 Markdown
- 最大行长度：100 字符
- 使用语义换行

### 文件组织

```
docs/
├── role-skills/           # 角色特定内容
│   ├── overview.md        # 英文版本
│   └── overview_zh.md     # 中文版本
├── ecosystem/             # AI 工具整合
│   ├── tool-name.md
│   └── tool-name_zh.md
└── community/             # 社区文档
    ├── faq.md
    └── faq_zh.md
```

### 命名约定

- 文件: `lowercase-with-hyphens.md`
- 图片: `descriptive-name.png`
- 分支: `type/brief-description`

### 内容规范

**应该：**
- 添加技能前充分研究
- 提供多个学习资源
- 考虑不同的经验级别
- 包含免费和付费资源
- 注明原始来源

**不应该：**
- 添加没有价值的推广内容
- 包含过时信息
- 使用有偏见的语言
- 侵犯版权

## 审核流程

### 提交后会发生什么

1. **自动检查**
   - Markdown 格式检查
   - 链接验证
   - 拼写检查

2. **维护者审核**
   - 内容准确性
   - 格式合规性
   - 范围一致性

3. **反馈和迭代**
   - 回应审核意见
   - 按要求修改
   - 推送更新到您的分支

4. **批准和合并**
   - 至少需要一名维护者批准
   - 压缩合并以保持历史整洁

### 审核时间线

- 初步回应：3-5 个工作日
- 完整审核：1-2 周
- 复杂更改可能需要更长时间

## 贡献者认可

### 贡献者名人堂

所有贡献者将：
- 在 CONTRIBUTORS.md 中列出
- 在发行说明中提及
- 有资格获得贡献者徽章

### 贡献级别

| 级别 | 标准 | 认可 |
|-------|----------|-------------|
| 🌱 首次 | 1+ 合并 PR | 在贡献者中列出 |
| 🌿 定期 | 5+ 合并 PR | 在 README 中提及 |
| 🌳 核心 | 20+ 合并 PR | 成为维护者 |

## 特定贡献领域

### 添加新技能

1. 检查技能是否已存在
2. 确定适当的类别和级别
3. 编写技能描述
4. 添加学习资源
5. 更新相关文档

**模板：**
```markdown
## 新技能类别

- [ ] **技能名称** - 它是什么以及为什么重要
  - 关键概念 1
  - 关键概念 2
  - 常见工具/框架

### 学习资源

1. **初级**: [资源名称](链接) - 简要描述
2. **中级**: [资源名称](链接)
3. **高级**: [资源名称](链接)
```

### 翻译内容

1. 复制英文文件
2. 重命名为 `_zh.md` 后缀
3. 翻译内容
4. 更新语言选择器链接
5. 保持格式

### 添加生态内容

新 AI 工具页面的结构：

```markdown
# 工具名称

## 概述
- 它是做什么的
- 主要功能
- 定价模式

## 可用技能
列出相关技能

## 整合指南
设置说明

## 最佳实践
有效使用技巧

## 资源
官方文档、教程、社区
```
